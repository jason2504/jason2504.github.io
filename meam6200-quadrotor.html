Course Overview & System Architecture

MEAM 6200 builds the complete autonomy stack for an aerial robot hierarchically — from low-level actuator commands up through full state estimation. The course is structured in two arcs. The first arc establishes the control and planning stack: geometric SE3 attitude control, 3D graph-search-based path planning, polynomial trajectory optimization, and final integration on physical hardware in a motion-capture environment. The second arc focuses on sensor-based state estimation, beginning with IMU-based attitude estimation, extending to feature-based stereo visual odometry, and culminating in a full Visual-Inertial Odometry system using an Error State Kalman Filter.

The hardware platform is the Bitcraze Crazyflie 2.0 (27g, STM32F405, MPU-9250 IMU, 2.4 GHz radio). For the control/planning arc, a Vicon motion capture system provides 6-DoF state at ~100 Hz. All high-level computation runs offboard on an Ubuntu/ROS desktop; only desired attitude quaternions (cmd_q) and total thrust (cmd_thrust) are sent over Crazyradio to the onboard firmware, which handles motor mixing at ~500 Hz using its internal attitude controller.

Part 1: Geometric SE3 Position Controller

The first component of the stack is a Proportional-Derivative (PD) position controller based on geometric control on SE(3). The controller computes a position error and velocity error from the desired trajectory, calculates a commanded acceleration using proportional and derivative gains (Kp and Kd), and derives the desired force vector by compensating for gravity. The total commanded thrust is extracted by projecting this desired force onto the quadrotor's current body z-axis.

The controller does not compute desired motor torques directly. Instead, the desired rotation matrix is derived from the commanded force direction and converted to a quaternion (cmd_q) that is sent over the radio to the Crazyflie. The onboard firmware runs its own high-frequency (~500 Hz) attitude rate controller using its internal IMU, handling the nonlinear attitude dynamics locally. This offloads the fast attitude loop to the onboard microcontroller where it belongs, while the slower position loop (bounded by Vicon and radio latency of ~10–20 ms) runs offboard.

A constant-velocity straight-line trajectory generator provided the initial desired position and velocity setpoints between waypoints. The controller was tuned to pass a comprehensive simulation test suite covering hover, step responses, and box patterns before hardware deployment.

Part 2: 3D A* Path Planning

The path planning module builds an occupancy grid from a JSON map at 0.12m voxel resolution with a 0.25m obstacle inflation margin (approximately robot radius plus safety buffer), then runs A* graph search on a 26-connected voxel graph using Euclidean distance as the heuristic. The heuristic is admissible and consistent, guaranteeing optimal paths. A priority queue (min-heap) expands nodes in order of f = g + h, where g is the cost-to-come and h is the straight-line estimate to goal.

The raw A* output contains hundreds of densely spaced nodes — many collinear, many clustered near start/goal. Two post-processing filters reduce this to a sparse set of meaningful turning points. A collinearity filter uses the cross-product criterion (sin θ < 10⁻⁶ threshold) to identify and remove redundant intermediate nodes while keeping all genuine direction changes. A distance filter removes nodes closer than 0.4m to each other, preventing waypoint clustering near corners. Together these filters reduce the raw A* path to a compact set of waypoints suitable for trajectory generation while avoiding obstacles.

Part 3: Minimum-Jerk Polynomial Trajectory Optimization

The trajectory planner generates smooth, dynamically feasible trajectories through the sparse waypoints using piecewise fifth-order (degree-5) polynomials — the minimum degree that can enforce C⁴ continuity (position, velocity, acceleration, jerk, and snap continuous at every interior waypoint). Minimum-jerk optimization minimizes the integral of squared third derivative across the entire trajectory.

For each axis (x, y, z) independently, the polynomial coefficients are solved by assembling a linear system whose constraints enforce: zero velocity and acceleration at the start and goal; position continuity at all interior waypoints; and C⁴ derivative continuity (velocity, acceleration, jerk, snap continuous) at each segment boundary. The resulting 6N × 6N system (N segments) is solved once offline in the constructor; during flight, the controller calls a simple polynomial evaluation function that computes desired position, velocity, and acceleration at any time t.

Segment durations are allocated proportionally to Euclidean distance at a fixed cruise speed (0.3 m/s for hardware), ensuring bounded velocity profiles throughout the trajectory and consistent deceleration into tight corners.

Part 4: Sim-to-Real Integration & Maze Flight

Transitioning the full stack from simulation to the physical Crazyflie required significant gain retuning. In simulation, the quadrotor is a perfect rigid body with instantaneous motor responses and zero latency. On hardware, Vicon noise and 10–20 ms radio latency excite high-frequency oscillations at aggressive gains, causing violent shaking or instability. The position proportional gains (Kp) were approximately halved and the attitude gains (KR and Kω) were reduced by an order of magnitude from simulation values. These reductions sacrifice some bandwidth but yield stable, smooth flight — the fundamental hardware constraint is that high gains request aggressive moments that physically saturate the motors before the control command can be acted on.

Controller Performance (Hardware Step Response)

A lateral (y-axis) step response was used to characterize the hardware controller. The system exhibited slightly underdamped behavior: rise time ~0.584s, overshoot 14.4% (estimated ζ ≈ 0.525), settling time ~1.498s into the 5% error band. A small steady-state offset (~0.024m) persists due to the absence of an integral term — the PD controller cannot eliminate accumulated constant disturbances such as battery weight imbalance or aerodynamic ground effect.

Part 5: IMU-Based Attitude Estimation

The second arc of the course shifts from Vicon-based state to sensor-derived state. The first estimation module implements a complementary filter that fuses gyroscope and accelerometer measurements from the IMU to estimate the quadrotor's orientation over time.

Gyroscopes measure angular velocity but drift over time due to integration of noise and sensor bias. Accelerometers measure the direction of gravity (when not accelerating) but are corrupted by linear acceleration and high-frequency vibration. The complementary filter combines both: the gyroscope provides high-frequency attitude updates through direct integration, while the accelerometer provides a long-term gravity reference to correct drift. A tunable parameter α controls the crossover between the two — higher α trusts the gyroscope more over short timescales; the accelerometer corrects accumulated drift on longer timescales.

The filter was validated against IMU data logs, with yaw drift quantified and the filter frequency response characterized. This forms the attitude estimation backbone that feeds into the more sophisticated estimation systems in subsequent modules.

Part 6: Stereo Visual Odometry with RANSAC

The visual odometry module estimates the quadrotor's 6-DoF pose change between consecutive stereo image frames by tracking visual features. The pipeline: detect keypoints in both the left and right camera images; match features across the stereo pair using epipolar geometry to triangulate 3D landmark positions; match those same features across consecutive frames; solve for the relative camera motion (rotation and translation) that best explains the observed 2D-to-3D correspondences.

RANSAC (Random Sample Consensus) is used to robustly estimate the motion in the presence of outlier matches — bad feature correspondences that would otherwise corrupt the pose estimate. In each RANSAC iteration, a minimal sample of 3 point correspondences is drawn, the relative pose is computed from that sample, and the number of inliers (correspondences consistent with that pose) is counted. The hypothesis with the most inliers is returned as the final pose estimate, with inliers refined by a least-squares optimization.

The module was benchmarked on the EuRoC MAV dataset, with translation and rotation error evaluated against ground truth. On its own, visual odometry accumulates unbounded drift — a limitation addressed in the next module.

Part 7: Visual-Inertial Odometry (Error State Kalman Filter)

The final module combines IMU propagation and stereo visual odometry in an Error State Kalman Filter (ESKF) — the state-of-the-art approach for onboard robot state estimation. Rather than estimating the full pose directly (which has non-Euclidean structure due to rotation), the ESKF maintains a nominal state estimated by integrating the IMU kinematics, and tracks a small error state around that nominal trajectory using standard linear Kalman filter updates.

Nominal State Propagation

IMU measurements (accelerometer + gyroscope) are integrated at 200 Hz to propagate position, velocity, and orientation. Accelerometer and gyroscope biases are estimated and subtracted in real time. This gives smooth, high-rate pose estimates between camera frames but accumulates drift from bias and noise.

Error Covariance Propagation

An 18×18 error state covariance matrix tracks uncertainty in position, velocity, orientation, accelerometer bias, and gyroscope bias. The discrete-time state transition Jacobian propagates this covariance forward, growing it with process noise as the IMU integrates between visual updates.

Visual Measurement Update

When a stereo camera frame arrives (~20 Hz), the 3D landmark positions predicted by the current nominal state are compared against observed feature locations. The measurement Jacobian H maps error states to predicted pixel residuals. A standard Kalman gain update corrects the nominal state and reduces covariance. Bias estimates converge as the filter learns the consistent disagreement between IMU propagation and visual observations.

The ESKF was validated on the EuRoC MAV dataset. Key convergence results: accelerometer bias plateaued at physically plausible values (az ≈ +0.35, ay ≈ −0.20, ax ≈ 0 m/s²); gyroscope bias converged to ωz ≈ 0.080 rad/s; gravity norm was confirmed at exactly 9.80 m/s²; the covariance trace dropped from its initial value to near zero as the filter gained confidence. Without visual updates, yaw drifted to −23° over the trajectory — demonstrating the necessity of the visual correction step and the observability limitation of yaw from IMU alone.

All 15 unit tests passed on the first submission. This module represents the convergence of all previous skills: IMU integration from the attitude estimation module, RANSAC-based feature matching from the visual odometry module, and Kalman filter theory from lecture.
